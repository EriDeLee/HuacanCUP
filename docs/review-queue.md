### P1 参考 DeepSeek Super-agent 的做法（2026-11-01 记下，到 M3、M5 再逐条定）

- 来源：仓库 github.com/deepseek-ai/dsh-superagent-prototype（只有一次提交 6337fc8，2026-10-31，MIT；README 写明是研究原型，

### D13 spec 的接口名怎么对应 design 里的网络

- 选了：**接口名 = 网络名**。`spec.interfaces[].name` 必须是 `design.json` 里某个网络的名字，对不上就在 G1 报
  `ir.spec_interface_net_missing`；负载 `between` 里写的网络、测量信号 `V(…)` / `I(…)` 里提到的网络、
  位号、引脚（`I(Q1.2)`）也都要在 design 里找得到，否则报 `ir.spec_signal_unknown`。
- 其他选项：每个接口再写一个 `net` 字段指定网络；接口直接写成连接器引脚（`J1.1`）；接口对应网络类。
- 理由：最简单，需求智能体少写一个字段，G1 一眼就能查；方案智能体起网络名时看着 spec 起就行。
  代价：接口名要符合网络名的规矩（不含空格和斜杠）；一个接口只能对应一个网络。
- 撤回：`Interface` 加 `net` 字段，`gates/ir_checks.py` 的 `check_spec_mapping` 改成查这个字段。

### D16 余量（margin）的定义，threshold 为 0 怎么办

- 选了：有符号的相对余量，`<=` 取 `(threshold − measured) / |threshold|`；`between` 下端按 `>=`、
  上端按 `<=` 各算一个，取较小的（离失败更近的一端）；**阈值为 0 时**：`pass.scale` 写了就拿它当分母，
  没写余量只表示方向（满足 +1，刚好 0，不满足 −1）。严格不等式刚好等于阈值时余量为 0 但判不通过
  （通过与否看比较结果，不看余量的符号）。写进了 PLAN §5.3，单测在 `tests/test_report.py`。
- 其他选项：阈值为 0 时用 |测量值| 当分母（结果永远是 ±1，没有量级信息）；余量取 None（排名时没法比）；
  统一用绝对余量（不同单位的余量没法放在一起）。
- 理由：0 阈值没有自然的量级，让写验收标准的人在需要时给出一个（`scale`）最诚实；不给也有确定的值。

### D32 自动摆放的算法：模拟退火，加三档合法化

- 选了：`分数 = 1.0·HPWL + 40·重叠 + 1.0·离板边 + 0.5·功能块 + 0.3·流向`，权重在 `config.yaml` 的
  `placement.weights`，各项都换算成 mm 量级：
  - HPWL：每个网络的焊盘中心的外包框的半周长之和（同号的几个焊盘都算；不足两个焊盘的网络不算）。
    验收对比用的也是这个数，由 pcbnew 重新读出来的位置算。
  - 重叠：每个 courtyard 向外鼓 `min_gap_mm / 2`（默认间隙 1.0 mm）以后两两重叠的穿透深度之和，
    加上 courtyard 出了允许区域（板框往里缩 `edge_margin_mm`，默认 1.0 mm）的距离。权重 40 等于硬约束，
    退火结束由合法化保证为 0。
  - 离板边：非连接器元件的 courtyard 离允许区域边界比 `edge_preferred_mm`（2.5 mm）近了多少。
    板边连接器不在这一项里：它是硬约束，每一步之后都贴回指定的那一边，不转，只沿着边滑动。
  - 功能块：同一个 `parts[].block` 里元件中心外包框的半周长（至少两个元件的块才算）。
  - 流向：从左边的板边连接器出发，沿信号网络（电源、地、引脚多于 8 个的网络不算）数跳数，给每个元件一个 0 到 1 的位置，
    分数是元件中心离 `区域左边 + 位置 × 区域宽度` 的距离。没有左边连接器就从右边连接器反过来排；两边都没有就没有这一项。
- 其他选项：每一项权重都是 1；按网络加权（电源网络轻、信号网络重）；加散热、位号文字的占位（见 P2）。
- 理由：线长是目的，功能块和流向是引导，所以放在线长的一半以下（0.5、0.3）；重叠要像硬约束。这组数是按量级定的初值，
  不是调出来的最优。
- 撤回：改 `config.yaml`，不用改代码。

### D34 封装的几何由 pcbnew 量；摆好以后重新读一遍再检查

- 选了：`kicad_side/footprint_geometry.py` 用 pcbnew 把每个封装转到 0 / 90 / 180 / 270 度各量一遍 courtyard 的外包框
  和每个焊盘的中心（相对封装原点），写成 JSON 给主程序。摆放只用外包框（矩形），不用 courtyard 的真实轮廓。
  没画 courtyard 的封装，用焊盘和图形的外包框外扩 0.25 mm 代替，并在 JSON 里标出来。
  不在网表里的封装（安装孔）当不能动的障碍。封装按位号排序输出（pcbnew 的顺序跟着文件里每次都不同的 UUID 走）。
  摆好以后用 pcbnew 把板子重新读一遍，合法性检查和 HPWL 都用重读的位置，不用算法自己的账。
- 其他选项：自己解析 `.kicad_mod`（要自己处理旋转的正负号、镜像、多边形 courtyard）；用真实的 courtyard 轮廓做碰撞（慢）；
  按封装名猜大小。
- 理由：几何由 pcbnew 自己算，不会和 KiCad 的 DRC 对不上；检查独立于算法。
  外包框比真轮廓保守（L 形、圆形的封装会多留一点空）。
- 撤回：`footprint_geometry.py` 输出多边形，`placement/geometry.py`、`score.py` 改碰撞判断。

### D35 种子怎么用：一路一个，需要时多试几个取最好

- 选了：默认一路只用一个种子（`placement.seed` 缺省 1，`placement.restarts` 缺省 1）；`restarts` 大于 1 时用
  seed、seed+1… 各摆一次，取分数最好的。实际用到的种子写进 trace 的 `placement` 事件（`detail.seed`），
  每次重来的种子和分数在 `detail.scores`。多方案并行（ADR-0016）时每一路把自己的种子传给 `place_board(seed=…)` 即可。
- 其他选项：一路固定试若干个种子；种子取自运行编号（每次运行不同，不可复现）。
- 理由：ADR-0018 问「一路只用一个，还是一路里试几个取最好」：默认最省时间，要质量时加大 `restarts`，不用改代码。
- 撤回：改 `config.yaml`。
