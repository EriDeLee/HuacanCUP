# ADR-0011 自写原理图版面引擎（样张）

- 状态：样张做完，机器检查全过。用户对照原图看过（2026-10-31）：「还不错，有点感觉，先这样吧」。
  完整版没有批准，暂不继续；M1 的原理图发射器走哪条路，等用户之后再定。
- 影响：PLAN §2「原理图生成」、§15 第 1 条风险、§16；接替 ADR-0009 里不能用的 SKiDL 画图
- 起因：用户要求原理图「只能比 original 好看」，ADR-0009 实测 SKiDL/schematizer 达不到

## 做法：主芯片 + 引脚链

代码：`eda_agent/emit/kicad_sym.py`（读符号库）、`sch_layout.py`（版面）、`sch_writer.py`（写 .kicad_sch）。

- 每个主芯片（引脚多的器件、连接器）是一个小团。它的每个引脚向外拉一条横线（链）。
- 链上依次是：串联的两脚元件、挂下来或挂上去的并联元件（另一端接电源或地）、末端的电源符号或网络标签。
- 电源和地只画电源符号，不拉长线；跨团的信号只画同名标签；没接东西的引脚打 NC 叉。
- 不在任何链上的两脚元件自成一团（旁路电容这类）。
- 相邻、接同一个电源的引脚合用一根总线和一个符号。
- 各条链竖直方向互相让开，离各自的引脚尽量近（带权保序回归求最小挪动）；拐弯的竖线按位置排列，保证互不交叉。
- 外面供电的电源网络放一个 PWR_FLAG，位置避开所有符号、文字、导线。
- 摆放全由代码按固定规则完成；UUID 由工程名和序号推出。同样的输入每次写出同样的文件（有测试）。
- 符号定义直接嵌入库里的原文，坐标全部落在 1.27 mm 网格上。

## 测试

- `tests/test_sch_layout.py`（15 个，不需要 KiCad）：KiCad 旋转约定、引脚朝向、网络分类、保序回归、
  版面质量检查「应报错」和「不应报错」各情形、网表一致检查的拆开/短路/缺脚。
- `tests/tools/test_sch_engine.py`（2 个，需要 KiCad）：LED 小电路写成 .kicad_sch，ERC、网表一致、版面质量、页内检查全过；输出可重复。
- 端到端测试发现过一个真问题：发光二极管本体外框比引脚长（光线箭头），引脚引出去的短线被误判为穿过本体。
  已改成「从引脚直接往外拉的线不算穿过」，并加了反例测试（往本体里拉的线仍然判失败）。

## 做的过程中发现并修好的问题

- KiCad 里属性文字的角度是相对符号的：符号转 90/270 度时，文字角度要写 90 才是横着的。
- 带路径前缀的网络名（`/pic_sockets/VCC_PIC`）要先去掉路径再判断是不是电源。
- 拐弯竖线的列不能按「挪得远的靠近芯片」排，要按位置排（往下挪的取最下面的靠近，往上挪的取最上面的），否则会交叉。

## 已知限制（样张版）

- 只支持单页、单单元符号；多单元符号（如 74LS125 的四个门）和派生符号（`extends`）会报错。
- 隐藏的电源引脚不画。
- 元件角色目前靠引脚数推断：3 脚以上或连接器当主芯片，2 脚共线当两脚元件。IR 还没有 `role` 字段，
  晶体管这类 3 脚器件也当主芯片摆，不一定好看。
- 两个主芯片之间的信号只用同名标签，不画直连线。
- 层次化、总线、差分对没做；页间连接用本地标签。
- 团的排列只是按输入顺序一行行排，没有按信号流向排。
- 导线交叉只计数、不判失败。
- 示例库的符号本身决定了引脚名文字的样子（例如竖排的引脚名），我们改不了。
